Section 1: Architectural Context & Execution Objectives
1.1 Purpose & Executive Objective
The objective of this engineering initiative is to implement, evaluate, and benchmark a production-grade SLM + LLM Cascade Routing Engine. The system routes natural language reasoning queries first to a local Small Language Model (SLM, running at zero marginal API cost via local inference) and conditionally escalates only failed or uncertain queries to a high-capacity Cloud Large Language Model (LLM via Groq API).

Beyond the operational routing mechanism, this project implements a rigorous, statistically grounded Evaluation & Deferral Harness. It generates an empirical deferral curve comparing actual router performance against three mathematical reference baselines:

All-SLM Floor: Zero escalations (f=0.0).

Random Router Control: Stochastic escalation at identical rate f.

Oracle Router Ceiling: Perfect escalation exclusively on SLM failures at rate f.

|                                      MONOTONIC STRICTNESS LEVELS                                   |
+---------+----------------------------------------------------+------------------------------------+
| Level 0 | Never Escalate                                     | Floor Baseline                     |

Section 7: Troubleshooting & Common Pitfalls
Windows CP1252 Unicode Errors:

Symptom: UnicodeEncodeError: 'charmap' codec can't encode characters during model output streaming.

Fix: Ensure _force_utf8_console() from src/config.py is invoked at top-level module load.

Missing Environment Variables Under uv run:

Symptom: GROQ_API_KEY is not set even if set in PowerShell.

Fix: Verify load_dotenv() runs before any os.getenv() calls in every standalone entrypoint. Always run with $env:PYTHONPATH=".".

Ollama Connection Refused:

Symptom: httpx.ConnectError: [Errno 10061] Connect call failed 127.0.0.1:11434.

Fix: Ensure Ollama background daemon is running (ollama serve or Ollama Windows tray app active).

SQLite Locking Contention:

Symptom: sqlite3.OperationalError: database is locked.

Fix: Configure sqlite3.connect(CACHE_PATH, timeout=30.0) and enable WAL mode (PRAGMA journal_mode=WAL;).

Section 19: Advanced Troubleshooting & Diagnostic Matrix
19.1 Purpose & Goal
To provide immediate resolution strategies for the most common environmental, hardware, or network failures encountered during execution.

19.2 Diagnostic Matrix
CUDA Memory Exhaustion:

Symptom: torch.cuda.OutOfMemoryError or local SLM crashing unexpectedly.

Fix: Verify that no other heavy VRAM applications are running on the HP Omen 16. The qwen3.5:4b model requires approximately 3.4 GB of VRAM; ensure the RTX 3070 has sufficient overhead.

Groq API Rate Limits:

Symptom: RateLimitError: 429 Too Many Requests when escalating.

Fix: Verify src/cache.py is actively preventing redundant calls. Check REQUEST_SPACING_S in config.py to ensure appropriate backoff between network requests.

SQLite Locking Contention:

Symptom: sqlite3.OperationalError: database is locked.

Fix: Ensure sqlite3.connect is initialized with timeout=30.0 and that the database is set to WAL mode (PRAGMA journal_mode=WAL;).
